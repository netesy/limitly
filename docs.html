Lymar Language & Tooling Reference

Official technical specification for the Lymar language grammar, static type system rules, standard library API modules, and compiler tooling.

1. Syntax & Formal Grammar Summary

Lymar features an unambiguous EBNF grammar parsed without operator conflicts. The grammar completely eliminates class/frame inheritance in favor of pure component mixins, embedding, and strict trait contracts.

Declaration ::= FrameDecl | TraitDecl | MixinDecl | FnDecl | VarDecl | ImportDecl
FrameDecl ::= "frame" Identifier [ ":" TraitList ] "{" FrameMember* "}"
FrameMember ::= [ Visibility ] ( VarDecl | FnDecl | "embed" Identifier ";" | "mixin" Identifier ";" )
TraitDecl ::= "trait" Identifier [ ":" TraitList ] "{" MethodSignature* "}"
MixinDecl ::= "mixin" Identifier "{" ( VarDecl | FnDecl )* "}"
FnDecl ::= [ Visibility ] "fn" Identifier "(" ParamList ")" [ ":" TypeAnnotation ] Block
Visibility ::= "pub" | "prot" | /* default private for vars/fns */

2. Static Type System, Fixed Widths & Zero-Cost Errors

Primitive types include platform-native int / uint, explicit widths i8–u128, single/double floats f32/f64, exact decimals d2–d6, bool, str, and nil.

Collection types are shorthand: lists [T], maps {K: V}, and tuples (A, B). Refined types attach SMT-verifiable predicates (type PositiveInt = int where value > 0;).

Fallible operations use zero-cost compiler error unions T? constructed via ok(val) or err(), and unwrapped/propagated via ? or ? else { ... }.

3. Pure Composition, Mixins & Embedding

Composition & Visibility Rules

  • Pure Composition: Frame inheritance is eliminated. Frames use mixin for state injection and embed for component method/field promotion.
  • Strict Trait Implementation (:): Colon is reserved exclusively for trait conformance contracts.
  • Protected Visibility (prot): Accessible within defining frames, embedded components, and module scopes.
  • Private Default: Declarations without explicit pub or prot default to private encapsulation.

4. Standard Library Module Breakdown

Comprehensive breakdown of built-in standard library packages:

std.collections

High-performance data structures: Vector, ArrayList, Queue, Stack, PriorityQueue, BitSet, and HashMap.

pub fn push(val: T): nil | pub fn pop(): T?
std.string & std.unicode

UTF-8 string manipulation, StringBuilder, Rune, regex pattern matching, and string formatting.

pub fn matches(val: str, pat: str): bool
std.math & std.linear_algebra

2D/3D/4D vectors (Vec2, Vec3, Vec4), transformation matrices (Mat4), and quaternions.

pub fn rotate(angle: float, axis: Vec3): Mat4
std.io & std.path

System file streams (File, FileSystem, Reader, Writer) and cross-platform path resolution.

pub fn read_to_string(path: str): str?
std.net & std.wss

Asynchronous TCP/UDP networking, HTTP routing, HTTPS SSL/TLS sockets, and WebSocket client/server streaming.

pub fn connect(addr: str): TCPClient?
std.crypto & std.compress

SHA-256 / SHA-512 digest engine (HashEngine), OpenSSL crypto wrappers, and zlib/gzip compression.

pub fn create_hash_engine(): Resource?
std.ui & std.game

Retained UI widget tree, IMGUI engine, Sokol GLES/Metal hardware graphics, and Truetype font rendering.

pub fn window(title: str, w: float, h: float)
std.time & std.process

Monotonic clocks (Instant), TimeDuration, DateTime, process execution (Command), and IPC pipes.

pub fn now(): Instant | pub fn spawn(): Process?

5. Compiler Commands & Tooling CLI

lymar run <file.lm> — Execute source file instantly via the Register VM driver
lymar build <file.lm> -o <binary> — Compile to native binary via Fyra AOT backend
lymar check <file.lm> — Perform semantic, type, and scope region analysis without emitting code
lymar fmt <file.lm> — Auto-format source code according to official style guidelines
lymar lsp — Start JSON-RPC 2.0 Language Server for VS Code / Neovim auto-completion & diagnostics
