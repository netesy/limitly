Learn the Lymar Programming Language

Welcome! This step-by-step tutorial takes you from writing your first lines of code to building high-performance systems, concurrent network services, and GUI applications with Lymar.

1. Getting Started & Hello World

Lymar is a compiled, statically typed systems language combining zero-cost abstractions, deterministic scope-bound memory management, pure component composition, and structured concurrency.

Create a source file named hello.lm: 

fn main(): int {
    print("Hello, Lymar World!");
    return 0;
}

main();

You can run your code instantly via the Register VM or build a standalone native binary:

$ lymar run hello.lm # Instant execution via Register VM
$ lymar build hello.lm -o hello # Compile to native binary via Fyra AOT backend
$ ./hello

2. Variables, Immutability & String Interpolation

In Lymar, mutable local bindings use var, while immutable bindings use val or const. Type inference is fully supported, but explicit annotations can be attached with a colon : Type. 

// Mutable variable
var counter: int = 10;
counter += 5;

// Immutable local value
val language = "Lymar";

// Constant binding
const MAX_BUFFER_SIZE: int = 4096;

// Rich String Interpolation with curly braces {}
print("Engine {language} updated counter to {counter} (limit: {MAX_BUFFER_SIZE})");

3. Primitive Types & Fixed-Precision Decimals

Lymar provides a rich set of primitives:

  • Integers: Platform-native int / uint and explicit widths i8, i16, i32, i64, i128, u8–u128.
  • Floating Point: float, f32, f64.
  • Fixed-Precision Decimals: d2, d4, d6, decimal (eliminates IEEE 754 rounding errors in financial/scientific logic).
  • System: bool, str, nil, any.
var price: d2 = 19.99;
var tax: d2 = 1.60;
var total: d2 = price + tax; // Exact decimal arithmetic

print("Total bill: ${total}"); // Total bill: $21.59

4. Built-in Dynamic Collections

Lymar features clean shorthand syntax for collections:

[T] — Homogeneous List
{K: V} — Dictionary / Hash Map
(T1, T2) — Heterogeneous Tuple
// Dynamic List [T]
var scores: [int] = [95, 88, 100];
scores.append(92);

// Dictionary {K: V}
var config: {str: int} = { "port": 8080, "workers": 4 };
print("Port: {config['port']}");

// Tuple (T1, T2) with dot indexing
var pair = ("status", 200);
print("Key: {pair.0}, Value: {pair.1}");

5. Control Flow & Loops

Lymar includes standard conditionals, C-style for, while, and modern range iter loops: 

// Conditionals
var score = 85;
if (score >= 90) {
    print("Grade: A");
} elif (score >= 80) {
    print("Grade: B");
} else {
    print("Grade: C or lower");
}

// Iteration over inclusive range 1..5
iter (i in 1..5) {
    print("Index: {i}");
}

// Iteration over collections
var fruits = ["Apple", "Banana", "Cherry"];
iter (fruit in fruits) {
    print("Fruit: {fruit}");
}

6. Pattern Matching (match)

match provides exhaustive pattern matching over literal values, enum variants, fallibles, and destructuring with where guards: 

enum Color { Red, Green, Blue }

var c = Color.Green;
match (c) {
    Color.Red   => { print("Stop"); },
    Color.Green => { print("Go"); },
    Color.Blue  => { print("Caution"); }
}

// Match with 'where' guards
var val = 42;
match (val) {
    x where x > 50 => { print("High"); },
    x where x > 0  => { print("Positive: {x}"); },
    _              => { print("Zero or negative"); }
}

7. Functions, Parameters & First-Class Closures

Functions support positional parameters, default parameter values, optional parameters, higher-order function arguments, and environment closures: 

fn add(a: int, b: int = 10): int {
    return a + b;
}

// Higher-order function accepting a lambda
fn apply(x: int, transform: fn(int): int): int {
    return transform(x);
}

val factor = 3;
var res = apply(5, fn(n: int): int { return n * factor; });
print("Closure result: {res}"); // 15

8. Pure Composition OOP: Frames, Mixins & Embedding

Lymar is a pure composition language without class/frame inheritance. Use mixin for state field injection, embed Component; for field and method promotion, and : strictly for trait conformance. 

mixin Identifiable {
    pub var id: int;
}

trait Printable {
    fn print_info();
}

frame Logger {
    pub fn log(msg: str) {
        print("[LOG]: {msg}");
    }
}

frame User : Printable {
    embed Identifiable; // Injects pub var id: int
    embed Logger;       // Promotes .log() method directly to User

    pub var username: str;

    pub init(user_id: int, name: str) {
        self.id = user_id;
        self.username = name;
    }

    pub fn print_info() {
        print("User #{self.id}: {self.username}");
    }
}

var u = User(101, "alex_dev");
u.print_info();                           // Output: User #101: alex_dev
u.log("Action performed successfully."); // Output: [LOG]: Action performed successfully.

9. Zero-Cost Error Unions (Type?) & Propagation

Fallible functions append ? to their return type. Values are returned using ok(value) or err(). Use ? to propagate errors or ? else for inline fallback blocks: 

fn divide(a: int, b: int): int? {
    if (b == 0) {
        return err(); // Construct fallible error
    }
    return ok(a / b); // Construct fallible success
}

fn calculate() {
    // Inline fallback handling with '? else'
    var val = divide(10, 0)? else {
        print("Division failed! Falling back to 0.");
        return 0;
    };
    print("Result: {val}");
}

10. Scope-Bound Memory Model & Region Safety

Lymar uses a deterministic, region-based memory model. All allocations are tied to lexical scope regions and freed automatically when the scope exits — with zero garbage collection overhead and zero manual memory management bugs! 

fn process_buffer() {
    var buffer = [1, 2, 3, 4, 5];
    {
        var temp = buffer; // Inner scope region
        print("Processing length: {len(temp)}");
    } // Inner scope region ends — temp memory deterministically released here

    print("Done processing");
} // Function region ends — buffer deterministically released here

11. Structured Concurrency & Channels

Lymar's concurrency is structured — task lifetimes are bound to the block scope. parallel handles CPU-bound multi-core work, while concurrent handles channel-based I/O tasks: 

var results = channel();

concurrent(ch = results, mode = batch, cores = 4) {
    task(i in 1..5) {
        // Perform concurrent work
        results.send("Result from task {i}");
    }
} // Channel auto-closes when all tasks complete

iter (res in results) {
    print("Received: {res}");
}

12. Modules, Imports & Standard Library

Organize code with clear module imports and filters using as, show, or hide: 

import std.math as math;
import std.collections show Vector, HashMap;
import std.io hide FileSystem;

fn main(): int {
    var vec = Vector();
    vec.push(42);
    print("Vector size: {vec.len()}");
    return 0;
}

main();
