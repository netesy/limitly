Module Overview

std/events Typed OS/window event pump and per-frame event queue. This is the SINGLE translation point from raw gg.poll_events() records into typed Event values. Both std.app (Fluent ui_context dispatch) and std.game (InputManager/IMGUI) consume the SAME per-frame event stream — neither calls gg.poll_events() directly, so events are never stolen between frameworks. Fan-out model: pump_events() builds a fresh event_queue once per frame. Every consumer reads events.pending_events() non-destructively, so any number of frameworks can observe the same stream. Events pushed via push_event() land in injected_events and are merged into the queue at the next pump — they live exactly one frame. pump_events() is also the frame-publish boundary on the GPU backend, so it must run exactly once per frame.

pending_events Function

pub fn pending_events(): list

The current frame's event list. Returns a copy — read-only for consumers, safe to hold across the next pump_events() (which replaces event_queue). Every consumer sees the same stream.

pump_events Function

pub fn pump_events(): nil

pump_events builds this frame's queue: it merges injected_events (synthetic pushes since the last pump) with freshly decoded native events from gg.poll_events(), then clears injected_events. It is the ONLY caller of gg.poll_events() above the gg layer — and the frame-publish boundary on the GPU backend — so it must run exactly once per frame.
