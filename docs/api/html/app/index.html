Module Overview

Application Module The single owner of window lifecycle, the event loop, and frame presentation for Lymar applications — UI apps and games alike. Usage (UI app — the common case): import std.app as app; import std.ui as ui; var a = app.App("Gallery", 1280, 800); a.ui(root); a.run(); Usage (game / custom loop — full control, locals stay in scope): var a = app.App("Game", 1280, 720); a.open(); while (a.is_running()) { a.pump(); // events -> queue + UI dispatch + frame dt // ... game logic, has access to a.delta_time() ... a.begin_pass(); // start GPU pass (clear color) // ... draw: scenes, std.gui, anything ... a.end_pass(); // draw hooks + retained UI on top + swap sleep(0.008); } a.close(); Optional per-frame hooks (module fn values — see std.ui.button for the same callback convention): a.on_update(fn(dt: float): nil { ... }); // after pump, before present a.on_draw(fn(): nil { ... }); // inside pass, before UI OS event pumping and the typed event queue live in std.events — this module only *dispatches* queued events into the component tree (std.ui.tree) and calls the registered hooks.

_dispatch_events Function

fn _dispatch_events(): nil

dispatch_events delivers this frame's std.events stream into the component tree. It reads events.pending_events() non-destructively, so std.game (or any other consumer) can observe the same stream — fan-out is the default, not the exception.
