Module Overview

std/ui/event.lm Type-Safe Event Handling & Fallible Event Propagation for Lymar UI Replaces untyped `any` callbacks and sentinel numbers with nominal enums, exhaustive match dispatch, and Lymar fallible types (`EventResult?`). A widget stores its callback in the `on_click_action` / `on_change_action` slot as a `fn(): nil` (the shape the retained renderer already invokes). `fire_action`/`fire_action_for` route that slot through a fallible pipeline so the dynamic `any` never leaks past this boundary: it is cast once, guarded, and a nil/absent handler becomes an `Unhandled` result rather than a nil check at every call site.

fire_action Function

pub fn fire_action(action): EventResult?

Invoke a widget's `fn(): nil` action slot fallibly. A nil action is not an error condition -- it is simply `Unhandled`, which removes the `if (w.on_click_action != nil)` guard from every dispatch site.

route Function

fn route(handler): EventResult?

Route an actionable event: fire the handler if one is bound (best-effort), then report the event as consumed. A nil handler is not a failure of routing -- the event was still handled by reaching a target.

dispatch_event Function

pub fn dispatch_event(evt: UIEvent, handler: any = ...): EventResult?

Full fallible pipeline: resolve the target, dispatch on the nominal kind via `match`, then invoke the handler. Returns `err()` when the event carries no target so callers can propagate with `?` instead of inspecting fields.
