win32.lm API Reference

Module Overview

std.native.win32 - Pure-Lymar Win32 windowing backend. Implements the std.native.types contract entirely through std.ffi: dynamic symbol resolution (user32/kernel32), hand-marshaled WNDCLASSEXA/MSG structs, and a Lymar WndProc exposed to Windows as a native trampoline via ffi.create_callback. No C glue, no sokol. Callback-safety design (important): The WndProc runs inside a libffi trampoline while the VM's outer frame may hold borrows on Lymar heap objects. Touching frames/lists inside the callback raises "Conflicting memory borrow" / "Invalid frame receiver". Therefore wnd_proc ONLY performs raw memory ops (ffi.load_*/store_*/ptr_add) and foreign_call. All window state and event queues live in ffi.alloc'd control blocks; poll_event / wait_event decode raw records into nt.Event frames in normal VM context where allocation is safe. Control block (i64 slots, 16 slots = 128 bytes): [0] hwnd [1] next block ptr [2] ring head [3] ring tail [4] ring count [5] ring capacity [6] closed flag [7] client width [8] client height [9] ring ptr [10] high surrogate [11..15] reserved Event record (16 i64 slots = 128 bytes): [0]kind [1]x [2]y [3]w [4]h [5]key [6]ch [7]mods [8]buttons [9]delta [10]handle [11..15]reserved x64 WNDCLASSEXA layout (80 bytes): cbSize u32@0, style u32@4, lpfnWndProc@8, cbClsExtra i16@16, cbWndExtra i32@20, hInstance@24, hIcon@32, hCursor@40, hbrBackground@48, lpszMenuName@56, lpszClassName@64, hIconSm@72 MSG (48 bytes): hwnd@0, message u32@8, wParam@16, lParam@24, time u32@32, pt@36
